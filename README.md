# CyberBounty — сайт брони для компьютерного клуба (демо)

Учебный проект для портфолио. Клуб, адрес, цены и отзывы вымышленные. Работает на компьютере владельца, без оплаты и хостинга.

**Что есть:** шапка, быстрая бронь (зона → дата/время/длительность → место на схеме зала → подтверждение), «О нас», «Услуги» (ПК, VIP, турнирные столы, PS5 Lounge, кальяны, бар, таблица характеристик), отзывы, политика конфиденциальности, мои брони, админка владельца (`/admin.html`).

## Запуск
1. `python -m venv .venv` и `.venv\Scripts\pip install fastapi uvicorn python-dotenv httpx pytest Pillow`
2. Файл `.env` (образец — `.env.example`): `ADMIN_PASSWORD=...` — пароль владельца.
3. `.venv\Scripts\python main.py` → сайт на http://127.0.0.1:8002, админка — http://127.0.0.1:8002/admin.html (или `start.bat`).

## Проверка
`.venv\Scripts\python -m pytest -q` — правила брони (пересечения, прошлое, часы 10:00–02:00, бронь не выходит за закрытие, цена, двойной клик) и сайт (вход, доступ, админка, защита).

## Как устроено
- Правила брони и цена — только на сервере: `app/booking.py` (скопировано из cyberbounty-bot, вместо Telegram ID — аккаунт сайта).
- Вход клиента: имя + телефон, без пароля и SMS (учебная версия); cookie `cb_session` на 30 дней. Один телефон = один аккаунт.
- Админка: пароль из `.env`, cookie на 12 часов, 5 попыток в минуту.
- Мгновенные обновления без опроса: long-poll `/api/wait`.
- Время клуба — Минск (UTC+3). Часы работы 10:00–02:00, ночные слоты после полуночи отмечены луной.
- Фото: Unsplash (лицензия Unsplash), список — `credits.html`. Исходники в `tools/raw`, единый цветокор делает `tools/grade_photos.py` (результат — `web/img/*.jpg`).
- Живой фон: градиент, частицы (canvas), сетка и синее свечение за курсором — `setupFx()` в `web/app.js`.
- Шрифты Exo 2 и JetBrains Mono (OFL) лежат в `web/fonts/`.

## Публичная демо-версия (без сервера)
`web/demo.js` включается сам, если сайт открыт не с Python-сервера (GitHub Pages или двойной клик по `web/index.html`): правила брони те же, «сервером» служит файл, базой — браузер посетителя (localStorage). Админка: `admin.html`, пароль демо — `demo`.
Локально через `python main.py` (адрес 127.0.0.1) демо не включается — работает настоящий сервер с базой. Принудительно демо: добавить к адресу `?demo=1`.
Публикация: `.venv\Scripts\python toolsuild_pages.py` (копирует `web/` в `docs/`), коммит, push; в GitHub: Settings → Pages → Branch `main`, папка `/docs`.


## Вход: Telegram и по телефону (код приходит в Telegram)
Все способы ведут в один аккаунт (таблица `users`: колонки `telegram_id`, `google_sub`, `email`, `phone`). Совпал любой — тот же человек; вошедший человек может привязать ещё один способ («Мои брони» → «Привязать вход»). Вход через Telegram проверяет сервер. Вход по телефону: человек вводит имя и номер, открывает бота, нажимает «Поделиться номером» — Telegram подтверждает, что номер его собственный, и бот присылает 6-значный код сюда, в Telegram (не SMS, бесплатно). Код действует 10 минут, одноразовый, 5 попыток. На демо-странице (GitHub Pages) настоящего входа нет: кнопка — «демо-вход» в один клик.

### Что настроить
Telegram — ничего настраивать не нужно: вход через ссылку на бота. Нужен только `TELEGRAM_BOT_USERNAME` в `.env` сайта и запущенный бот на той же базе.

## Единая бронь сайта и бота (mini app)
Один источник правды — одна SQLite-база (`data/pcclub.db`) и один набор правил (`app/booking.py`, `app/accounts.py`). Бот и mini app (папка `cyberbounty-bot`) работают с этим же файлом: у бота в `.env` стоит `DB_PATH` на базу сайта, а Telegram-человек получает ту же строку в `users`, что и на сайте после входа через Telegram. Поэтому занятое место видно сразу везде, пересечения невозможны (проверка и запись — в одной транзакции), а мои брони видны и там и там. Сайт и бот должны запускаться на одном компьютере (база — файл). Обновления между ними приходят в течение пары секунд (сверка отпечатка броней в `/api/wait`).
Старые брони из отдельной базы бота переносит один раз `tools/import_bot_db.py`.
