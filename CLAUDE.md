# CyberBounty (сайт) — правила проекта

Название клуба везде только по-английски: **CyberBounty**. Интерфейс по-русски.

## Решения
- Продолжение демо-бота `D:\проекты\боты\cyberbounty-bot`: тот же бренд (неон, амбер + циан), те же правила брони.
- Структура сайта — под быструю бронь: герой → бронь → о нас → услуги → отзывы → подвал с политикой.
- Публичная демо-версия на GitHub Pages работает без сервера (`web/demo.js`, данные в браузере посетителя); настоящий сервер (FastAPI) — для локального запуска. Правила брони живут в двух местах: `app/booking.py` и `web/demo.js` — при изменении правил менять оба.
- Учебная версия: без онлайн-оплаты и платного хостинга; клуб, цены, отзывы вымышленные (сказано в подвале).
- Вход: Telegram и запасной имя+телефон — всё в один аккаунт (`app/accounts.py`). Ссылки на соцсети и бота — в `web/site-config.js`.
- Бот и mini app (`cyberbounty-bot`) работают с ТОЙ ЖЕ базой, что сайт (`DB_PATH`); `booking.py`, `accounts.py`, `db.py` в боте — копии сайтовых, при правках менять оба.
- Цену и все проверки делает сервер (`app/booking.py`), клиенту не доверяем.

## Правила, которые нельзя нарушать
- Нет пересечений на одном месте; нет прошлого; часы 10:00–02:00; бронь не выходит за закрытие; двойной клик = одна бронь.
- Админка только по паролю из `.env`; секреты не печатать и не коммитить.
- Анимируем transform/opacity, ничего не должно прыгать (фиксированные высоты, `minmax(0,1fr)` в сетках).
- Проверять телефон (375) и компьютер (1440) после любой правки вёрстки.
- Фото только со свободной лицензией (Unsplash), источники — на `web/credits.html`; все фото пропускать через `tools/grade_photos.py`, чтобы был один цветокор.
- Не рисовать картинки кодом (владелец отверг): только реальные фото.
- Не анимировать фильтры и `background-position` больших слоёв (лагает); не вешать `backdrop-filter` на карточки.
- Версии файлов в ссылках (`?v=...`) ставит `tools/build_pages.py` сам (хэш содержимого `web/`); руками не менять. После любой правки: сборка → коммит → push → слияние в `main`.
