# Правка для бота (`cyberbounty-bot`)

Бот работает с той же базой, что и сайт, а `booking.py` и `db.py` в боте — копии сайтовых (см. `CLAUDE.md`).
После последней синхронизации (коммит `87c3dd8`) на сайте изменилось три правила, и бот нужно привести в соответствие.

## Что изменилось

1. **Клиент отменяет бронь в любое время**, в том числе когда игра уже идёт; нельзя отменить только закончившуюся.
   Из `cancel_by_client` убрана ошибка `started` («Бронь уже началась…»).
2. **«Убрать» и «Очистить» в списке клиента больше не удаляют бронь из базы**, а скрывают её у клиента:
   новая колонка `bookings.client_hidden`. Админка, статистика и владелец видят всё как раньше.
   Если в боте останется старый `DELETE`, у клиента бронь пропадёт насовсем, а у владельца тоже; если не будет фильтра `client_hidden = 0`, клиент в боте снова увидит «убранные» брони.
3. **Админский обзор дня** показывает брони, начавшиеся накануне и идущие за полночь (с пометкой `carried`).

## Как применить

Самый надёжный способ — заменить файлы целиком (в боте они и должны совпадать с сайтовыми):

| Из сайта | В бот |
|---|---|
| `app/booking.py` | копия `booking.py` |
| `app/db.py` | копия `db.py` |

Если файлы в боте менялись отдельно, применить патч (из папки, где лежат эти файлы; путь внутри патча — `app/…`):

```
git apply --check --directory=<папка_с_booking.py_в_боте> tools/bot_sync/booking_db.patch
git apply --directory=<папка_с_booking.py_в_боте> tools/bot_sync/booking_db.patch
```

Колонка `client_hidden` добавится в существующую базу сама при первом запуске `init_db` (старые данные не затрагиваются).

## Что проверить в самом боте (там, где логика, а не копии)

Поиск по папке бота:

- `started` и `началась` — текст/обработка ошибки «бронь уже началась»: убрать, отмена теперь возможна всегда, пока бронь не закончилась;
- `start` рядом с `cancel` / `Отменить` — условие показа кнопки отмены вида `start > now`: заменить на `end > now`;
- `DELETE FROM bookings` в коде клиентских действий (удаление/очистка) — заменить на `booking.delete_by_client` / `booking.clear_mine` из обновлённого `booking.py`;
- свои SQL-запросы «мои брони» — добавить `AND client_hidden = 0` (если список берётся через `booking.my_bookings`, это уже есть).

## Проверка

После замены файлов запустить тесты бота. Вручную: создать бронь на время, которое уже идёт, отменить её в боте — статус `canceled`, место сразу свободно; убрать отменённую бронь у клиента — в админке сайта она остаётся.
